# Local Agent Notes

## Docs Posture

- Keep `README.md` primarily user-facing, especially the install flow, quickstart, and first-use path.
- Prefer putting deeper implementation detail, internal notes, and developer-facing reference material in `CHANGELOG.md`, `DEVELOPMENT.md`, and `ARCHITECTURE.md`.
- When updating docs after a feature lands, preserve README clarity first and link out rather than turning the README into an internal reference dump.
- This is a general guideline, not a rigid split. The current balance is fine; aim to keep it approachable for users while still leaving good breadcrumbs for developers and future agents.
