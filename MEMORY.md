# Memory

- Surprise encountered during Phase 3 daemon work: macOS `AF_UNIX` socket paths are short enough to fail with long temp-directory paths. Prefer short socket paths (for example under `/tmp` in tests) and treat stale/non-socket socket-path errors as "daemon not ready" during client health checks.
- Surprise encountered during Phase 4 menu-bar packaging: keep `setup.py` self-contained. Importing `que.*` from `setup.py` breaks uv/setuptools isolated editable builds before the package is importable.
- Surprise encountered during Phase 4 menu-bar follow-up: older URL cache entries could overclaim `in_library` / `downloaded` even when Music.app had not ingested the track. Revalidate those cache states against the current library, and treat "moved to folder but Music.app missed it" as retryable import work, not a successful finished import.
- Surprise encountered during library matching follow-up: `rapidfuzz.token_set_ratio` is too permissive for remix/version titles because `"song (2019 mix)"` vs `"song"` can score as a perfect match. Keep cache verification strict, and keep title-version tokens sticky enough that variants download instead of being skipped as plain duplicates.
- Surprise encountered during daemon/menu follow-up: YouTube watch URLs often carry `list=` / `index=` mix context even when the user's intent is a single song. Do not treat raw `list=` presence as playlist intent; canonicalize `watch?v=...` and `youtu.be/...` to single-track jobs unless the URL is an explicit `/playlist?list=...` target.
- Surprise encountered during metadata follow-up: anonymous `yt-dlp --no-download` lookups can hit YouTube's "Sign in to confirm you're not a bot" wall even when the same URL works with browser cookies. Retry metadata lookup with Chrome cookies before treating it as a hard metadata failure.
- Surprise encountered during cache follow-up: `failed` and `skipped` cache statuses are not durable state. Keep them for history, but never let them short-circuit a future run; retry the URL instead.
- Surprise encountered during packaged-app metadata follow-up: py2app-bundled Python can leak Python bootstrap env such as `PYTHONHOME` into child `yt-dlp` processes. Homebrew `yt-dlp` then imports against the bundled stdlib, which omits `optparse`, and fails before metadata/download work starts. Strip Python bootstrap vars and prepend common Homebrew/user bin paths for every `yt-dlp` subprocess.
